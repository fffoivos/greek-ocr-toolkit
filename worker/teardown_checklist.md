# Before the worker box is deleted

Deletion remains the owner's action. Do not delete a box with an unverified transfer or an unresolved paid read.

- Stop collection with `bash worker/status.sh --stop`; wait until status is `stopped`. Preserve the PID/exit/state evidence. Confirm no foreground collector is running.
- Resolve every uncertain ledger read with the coordinator. Count `reserved`, `request_started` and `response_saved` separately; reservations are a safety ceiling, not proof of billed OCR.
- Run `bash worker/sync_back.sh '<DESTINATION>'`, inspect the dry run, then `bash worker/sync_back.sh --execute '<DESTINATION>'`. Require `execute=true`, `post_sync_checksum_match=true` in the local `sync_receipt.json`.
- On the destination run `sha256sum --check retained_SHA256SUMS` and require every file to pass. Keep the checksum manifest, local sync receipt and exact code commit. Verify manifests, page records, consistent SQLite ledger, rasters, raw responses, cards/keys/verdicts, resolution bindings and any retained-PDF exceptions are present. Check read-page raster/response hashes, not just file counts. The original absolute output path is needed for regeneration; retain it in the handoff.
- Compare the ledger with **Google Cloud billing** for the pinned project, EU processor/version, execution dates and read-page count. Allow for reporting delay and invoice rounding. Record the ledger micro-USD total and billed SKU/units/amount, explain any discrepancy, and preserve the coordinator's reconciliation. A ledger reservation or an email is not billing proof. No Google billing request is part of these scripts.
- Remove credentials from the box: stop any process retaining the token, `unset COLLECT_V3_ACCESS_TOKEN GOOGLE_APPLICATION_CREDENTIALS`, and have the owner delete their credential file from the separately recorded secret location. Revoke/expire the short-lived token or revoke a service-account key if it was created just for this box. Confirm the retained payload, shell history, logs, configs and snapshots contain no credentials; never paste the token into a checklist or receipt. Do not save the environment or use `ps e`.
- Keep the shared limiter's rolling-24h state if collection may continue on a replacement worker; verify the synced `shared_limiter/` snapshot and restore it on the replacement without resetting its timestamps. Do not treat deletion of the box as a reset of the MDZ allowance.
- Only after checksum verification, billing reconciliation and credential removal does the owner delete the box and any provider snapshots/volumes they intend to remove.
