# Outline for AGENTS.md and README.md (coordinator, 19 Oct 2026) — Sol drafts from this; the coordinator reviews

## README.md (for a reader who knows OCR but not this repo)
1. What this repository is: the private toolkit for the Greek OCR programme — every tool behind typed APIs with tests (owner standard, 8 Oct 2026). Two aspects, kept apart: (A) development of the OCR model and our segmenters; (B) creation of training data for OCR.
2. Map of the repo by the owner's taxonomy (the table in PLAN.md, trimmed): where the code is, where the documentation is, one line each. A.i slow pixel segmenter (`greekocr/pages`), A.ii next-generation stack R8, A.iii the small-detector stack R7 (record), recogniser/synthetic/scoring; B.a Google OCR on pages (`greekocr/readers`, source collectors), B.b correction and filtering tools (sf7 polytonic, RU1 Cyrillic, N1 numerics, dashes, segmentation filter 0.9-s4, content gate 0.3), B.c the line pipeline (the organising process of B; `pipeline.mmd`), B.d the revision pipeline (owner review sheets, artifacts, marks).
3. Current versions (one table, from `tool_versions.json`): pipeline 0.3, segmentation 0.9-s4, content gate 0.3, final eligibility 0.3, polytonic sf7, RU1 0.3, N1 0.2, dashes 0.1, codec v2/v2.1, benchmark 0.1.
4. How to run: install, tests (`.venv/bin/python -m pytest -q`), the CLI, the pipeline preflight command, where Clariden job kinds are described.
5. Data policy: no tracked file over 5 MB; bulk artifacts live outside the repo under the data root with receipts in `docs/records/`; crops and sheets are never committed.
6. Where the history is: `docs/records/` (reports, hand-offs, receipts by track), old branches kept as history, the clean-up record (`docs/cleanup_20261019/`).

## AGENTS.md (the process; for any agent or person working here)
1. Roles: the owner decides (rules, gates: push/merge, spend, launches, irreversible actions); the coordinator plans, briefs, reviews and records; Sol (gpt-6.1-sol via codex) executes code and operations from briefs; track leads (Opus sessions) own one track each and brief Sol; Astra reviews packages at checkpoints. No agent adds rules the owner did not state; tools implement the owner's rules exactly.
2. The two aspects and the rule that they stay apart: (A) model and segmenter development never consumes B's review artifacts as truth; (B) training-data creation uses A's segmenter as a frozen tool version. A change to a segmenter is a new version with a replay on the frozen review sets before B adopts it.
3. The B process, as the pipeline graph defines it (B.c): bind raw rows → inventory and expected scripts per document → content gate (unexpected script HOLD, mixed-script word DROP, short lines DROP, cells with >1 letter-or-digit exempt) → segmentation screen (0.9-s4: whole-word gate, 90° turn, curved baselines, ink box for small crops, band 0.30–2.00) → schedule every correction tool (sf7, RU1, N1, dashes) → compose and re-inventory → final eligibility → hold-out protection and dedup → immutable export with receipts. Every decision carries its reason; holds and drops retain evidence; nothing is admitted without a tool result where a tool applies.
4. The revision pipeline (B.d): every tool change is shown to the owner on a review sheet built by `greekocr.adjudicate.owner_sheet` (crop + text together, last two tool versions, outer border = owner mark, inner frame = tool verdict, keys, autosave to the artifact database, never write on load, unjudged lines first, cards fit the screen, vertical crops side by side); marks are dumped before every republish and stored with the tool's evidence; the owner's marks are the standard the tools are scored against (owner standard: one central line, text = visible line exactly, ≤ 2 whole neighbour words at 100% visibility).
5. Briefs and runs: one brief per Sol run under `docs/ocr_program_2026-10-06/briefs/`, one objective, inputs by sha256, outputs by path, tests named; one-line report back; hand-off documents per track; receipts for every produced artifact (path, bytes, sha256, producing commit). Sol runs cannot write git metadata: commits, merges and pushes are done by sessions, never by Sol.
6. Clariden operations: verify deploy (sha compare) before any sbatch; leads never submit; partition and time per job kind; smoke then full; read the log on FAILED; monitored, never fire-and-forget.
7. Data and secrets: data root outside the repo; receipts in git; credentials only in the macOS Keychain, injected at launch; nothing from Anemi leaves the project; ≤ 1 request/s per host.
8. Reviews: Astra at checkpoints with the owner's brief verbatim; third review cycle on one object = stop and decide; summaries never stronger than the table rows.
9. Where things are: the taxonomy map (README §2) and `docs/records/` index.
