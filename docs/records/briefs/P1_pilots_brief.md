## A. Collection pilots (per the S1 shortlist; ≈ 400 read pages ≈ USD 0.60)
For each: fetch the listed pages (20–40 pages per document, mid-body plus front matter and back matter so headings, contents and indices are included), render at the capped long side, run the page detector, read with Document AI, apply admission **with the data-plan carve-outs** (caps lines ≥3 letters at confidence ≥0.89; digit-dominant lines admitted when digits ≥40% of visible characters; leader runs kept with a canonical dot-count label; tall-box headings via a heading crop path), classify lines (script class + line tags), run the G1b geometry audit on the pages, and produce a 20-page contact sheet for the owner's look.
1. Internet Archive historical Greek print 1850–1890: 3 documents, 100 pages (new discovery per S1; print only).
2. Internet Archive 1900–1982 Greek: 2 documents, 60 pages.
3. BSB/MDZ Philologus: 50 pages including the contents leaf (headings, leaders, Greek+Latin mixed lines).
4. ELSTAT historic yearbook or ΦΕΚ scanned issue: 50 pages (numeric tables).
5. Kosmopolis periodical: 50 pages (dialogue/fiction, caps, ads).
6. Open Archives `ocr_success` documents: 3 documents, 60 pages (modern scanned, non-parliament).
7. Ajax commentaries / GT4HistComment ground truth: no Google read; fetch the published line GT + images; report mixed-line share and how many lines pass our admission.
Report per pilot: pages fetched/rendered/read, lines by class and tag, admission yield per rule, geometry-audit positive rate, mixed-line share, rights record per item, USD spent, contact-sheet path, and the measured **usable rows per read page per target class** that the data plan's quotas need.

## B. Alignment pilot (3 sources × 50 pages; ≈ USD 0.25)
Greek Wikisource (validated pages with Commons scans not among the 400 already used), Project Gutenberg Greek (one ebook whose cited scan is on Internet Archive), and one Perseus/First1KGreek edition whose TEI header names a scanned edition on Internet Archive. For each: fetch text + scan pages, read the scan with Document AI, align the proofread text to the page read (sequence alignment on NFD; record transformations such as DP header stripping and TEI `choice` resolution), assign line labels from the proofread text where the alignment is unambiguous, and report under the data plan §6.1 release contract: witness binding (edition, page hash, text revision, status), literal span ownership, coverage over all sampled pages (retained characters/lines, rejected regions and reasons), and a 40-line blind sample sheet (accepted and rejected mixed) for the coordinator's adjudication. Yield = lines with human-text labels per read page.
