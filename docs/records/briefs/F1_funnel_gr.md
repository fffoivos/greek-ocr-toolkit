## What to measure per source (the owner reads one row per source)
1. **Access path verified Y/N**: Y only if a fresh individual page raster (or a PDF page you render) was fetched and decoded in this run. Record the exact URL pattern (item → page), auth needed, robots.txt result.
2. **Fetch rate and success**: ≥ 50 page fetches spread over ≥ 5 different items (fewer only if the source blocks earlier — then record why), sequential at the polite rate below. Report pages/min sustained, median and p90 seconds per page, bytes per page, success %, failure modes with counts (HTTP status, timeouts, CAPTCHA/HTML instead of image, truncated PDF, robots). For whole-PDF sources: PDFs/min, MB per PDF, pages per PDF, and time to first page. For the large sources (IA, Open Archives, BSB) also one short run at concurrency 3 (≤ 60 fetches) to see whether throttling starts; stop at the first 429/503 and record Retry-After.
3. **Supply**: candidate items **with page access** per period and target class, as `candidates_<source>.jsonl` (id, title, year, decade, language/script evidence, page count, page-access route, restriction flags, overlap flag with collected/test books, rights fields). Counts per decade in the report. A catalogue hit without page access does not count. Where the language tag is unreliable, verify script on one fetched page per sampled item and report the verified share on a sample of ≥ 20 items.
4. **Blocker**: one sentence, with the receipt that shows it.
5. **Workaround / alternative**: the concrete next route if blocked (official API/IIIF/export, a mirror of the same scans, another source covering the same class).
6. **Rights per item**: record scan rights, text rights, access terms URL, licence string as published. Owner: rights are a record, **not a gate** — do not stop on rights.

## Rules (never break)
- ≤ 1 request/s per host unless the host documents a higher rate; honour robots.txt and Retry-After; on 429/503 back off (60 s, then 300 s) and after the second, stop that host and record it. Contact User-Agent: `greek-ocr-research/0.1 (foivos.karounos@gmail.com)`.
- No CAPTCHA solving, no login we do not hold, no bypass of access controls, no scraping of a viewer the site forbids in robots.txt. A refusal is a finding, not a problem to engineer around.
- Credentials only from the environment (never written to files, logs or receipts).
- **Disk is tight (Mac has ~20 GB free).** Keep at most 400 MB of page images for this track; store pages as grayscale JPEG, long side ≤ 2000 px, after measuring the original bytes; delete nothing outside your own output directory. Bulk images go under `docs/records/harvest/funnel_v1/gr/bulk/` and are git-ignored (add a `.gitignore` there).
- Wall clock: aim for ≤ 4 h. If a single source eats > 40 min without a verified path, record the blocker and move on.
