### C2-B01 — BLOCKER: L1 accepts corrections despite recorded unknown or uncertain evidence

**Code path.** `L:scripts/labelfix/m2_run.py:122–142` indexes coverage but reads its reason only when the R1 prediction is missing. A present prediction bypasses `coverage.evidence_state=UNKNOWN` and `coverage.uncertainty`. **Reproduction.** On both reviewed checkouts, the real M2 composer accepts detector-none/R1-none with each of: R1 `UNKNOWN/no_pixel_evidence`; R1 `UNKNOWN/out_of_image_span`; detector `segmentation_uncertain=True`; detector top/bottom clipping flags. Both modes return unheld `α`. In the L1 checkout, the real overlay function changes original `ά` to `α` with status **`corrected`**, in both PRESENCE and FULL. These are synthetic policy counterexamples, not measured production error rates (`new_probes_l1.json`).

This is not solely hypothetical state reachability. The saved mock keeps **four segmentation-uncertain slots on one line**, `592f0823e0984204631241d8-p000020-l0012`, starts 27, 28, 48, 49, in both 34-line kept sets. That line is unchanged, so it does **not** demonstrate a wrong corrected label. The same saved kept sets contain **262 clipping flags across 25/34 lines**. Those coarse edge flags can be neighbouring ink and are **not 262 demonstrated truncated marks**. No R1-UNKNOWN slot was found in the kept mock. The strongest evidence is the executable correction-gate counterexample, supported by actual propagation of segmentation uncertainty into kept output.

**Concrete fix.** Make the shared composer/release gate consume R1 uncertainty and detector unresolved ownership/segmentation. A prediction cannot turn absent/invalid observation into evidence of no mark. Preserve fused-but-resolved cases; do not ban all fused samples or restore a connected-component admission veto. Define relevant directional observability from validated crop/source masks; until then, route unresolved relevant clipping to review rather than silently certifying absence. Export these states with every overlay decision. Recompose/re-filter saved detector/window/R1 records under a new bound policy where sufficient evidence was retained; do not label old outputs repaired merely by changing the manifest. This safety gate does not require changing the trained R1 window or waiting for R2 retraining.

### L1 parity gate and release format

The in-job gate is correctly **before training-crop alignment/detection** (`L:scripts/labelfix/clariden/l1_run.py:35–53`). The parity inference uses batch size **64** (`l1_verify.py:58`), while production inference defaults to **512** (`l1_infer.py:49,75–80`); therefore the gate is not an exhaustive guarantee across production batch shapes or all crops. Qualify the actual production execution shape when updating the gate. The saved **32/32 exact** result is a mock/local receipt, not proof that job 3679313 passed its node gate.

The overlay/release design has several sound safeguards (`L:scripts/labelfix/clariden/l1_common.py:43–82,99–169`):

- Original source bytes are preserved; each overlay binds the original label hash, model/policy hashes, status and proposed label.
- Edit offsets are **original-label NFD offsets**. Evidence slot offsets are **recogniser NFD offsets**, explicitly separate. Consumers must honor that distinction.
- Any emitted HOLD rejects the **whole line**. Base/non-whitelisted-punctuation disagreement rejects the line, subject to the overbroad combining-mark exception in C2-M01.
- Duplicate/unknown runtime IDs and incomplete coverage fail; corrected/unchanged are the only kept statuses.
- Each corrected variant has a control containing the **exact same kept IDs and ORIGINAL labels**, and the written control payload is checked, not merely an in-memory alias.
- Manifests bind overlays, selections, kept IDs and sources; status coverage is reported per actual wave and source.

The saved mock has **5 corrected, 29 unchanged, 126 HOLD**, with **34 matched control IDs** in each variant. My readback verifies both overlay, kept-ID and control hashes. I viewed the five corrected native lines plus the retained segmentation-uncertain line. The crop views provide limited plausibility checks for particular mark proposals/punctuation normalization; they do not establish a correction precision, resolve every tiny mark, or cure the policy counterexamples.

`l1_run.py:74–81` writes a final complete run receipt only after release generation and source recheck. A timeout can leave shards or release files without completion. The local reviewed artifacts establish the mock and deployment preparation, not production completion. The actual job’s run receipt, node parity, complete shard/overlay hashes and counts must be read before claiming a production release exists.

The paired control is the right design for testing label changes **conditional on the same selected lines**. It does not by itself compare selection against the full original corpus or remove selection bias. Wave 1c must select exactly one bound variant, use its exact kept set for both arms, load corrected/unchanged labels from that release, and exclude HOLD/out-of-scope rather than falling back to original labels. A training consumer is not implemented or validated by the overlay writer alone.
