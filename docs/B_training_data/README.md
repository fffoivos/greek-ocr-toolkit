# B — creation of OCR training data

This process turns sourced pages and Google OCR observations into version-bound, reviewable training rows. It uses A's segmenter as a frozen tool; developing that segmenter belongs to [A](../A_ocr_development/README.md). The [B.c pipeline](c_pipeline/README.md) organises all four parts and defines the implemented stage order, admission decisions and output contracts. Its [graph](c_pipeline/pipeline.mmd) is the process map.

| Owner's part | Work and starting document |
|---|---|
| **B.a — running Google OCR on pages** | Acquire and bind source pages, processor identity, raw responses, line observations and costs. Start with [Google page reads](a_google_ocr/README.md); use [sources and split custody](a_google_ocr/SOURCES.md) for source regimes, frozen cohorts and known limitations. Historical collector admission flags do not certify current eligibility. |
| **B.b — correcting and filtering with tools built on A** | Apply the versioned [tool set](b_tools/README.md): [segmentation filter](b_tools/SEGMENTATION_FILTER.md), [content gate](b_tools/CONTENT_GATE.md), [polytonic SF7](b_tools/POLYTONIC_SF7.md), [Cyrillic RU1](b_tools/CYRILLIC_RU1.md), [numerics N1](b_tools/NUMERICS_N1.md) and [dash tags](b_tools/DASHES.md). Use the [Label Quality Benchmark](b_tools/LABEL_QUALITY_BENCHMARK.md) with its actual coverage and exposure restrictions. Tool KEEP is one stage's decision; unresolved correction evidence remains HOLD. |
| **B.c — the exact organising pipeline** | Bind and inventory all raw rows; apply the content gate and segmentation screen; schedule applicable corrections; validate and compose edits; re-inventory; apply final eligibility, hold-out protection and deduplication; export an immutable generation with receipts. Start with the [pipeline](c_pipeline/README.md) and [Clariden runbook](c_pipeline/RUNBOOK_CLARIDEN.md). |
| **B.d — revision, artifacts and human publication** | Replay a proposed tool version on frozen evidence, preserve owner marks, render crop and text together, publish for review, and bind returned judgments to the version and evidence. Start with the [revision workflow](d_review/README.md), [sheet contract](d_review/HUMAN_REVIEW_SHEETS.md) and [publication protocol](d_review/PUBLISHING.md). [Blind review](d_review/BLIND_REVIEW.md) and [agent readers](d_review/AGENT_READERS.md) describe separate print-truth custody. |

The live [tool manifest](../harvest/line_pipeline/tool_versions.json) identifies pipeline 0.3.2's component generations: segmentation 0.13 (label 0.9-s5), content gate/final eligibility 0.3, polytonic 0.7, Cyrillic 0.3, numerics 0.3 and dashes 0.1. Segmentation is frozen as accepted; SF7 remains `candidate_pre_audit`, N1 is assisted, and dashes only tag. Historical deployed packages and their outcomes stay attached to their recorded versions. This layout does not adopt a candidate or establish a fresh population result.

Bulk data lives outside the repository with [custody receipts](../cleanup_20261019/data_out/MOVE_MANIFEST.tsv). Use the [records index](../records/INDEX.md) for dated evidence and handoffs, and [shared infrastructure](../shared/README.md) for package contracts and operations.
