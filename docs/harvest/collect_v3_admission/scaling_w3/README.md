# SCALE1 — unique-row scaling package

The 20 October coordinator ruling governs: no edition cap and no series cap. Every row in a class is selectable. The benchmark defaults (50/class/edition and 150/class/series) are benchmark-diversity rules; they are not used here. `vendor/bench02_draw.py` is an unchanged copy of HEAD e6365239b4d087404a7a8a1c20609a0ea1ec2dad, imported by the wrapper, SHA-256 aa950a88f02b083ce4ffb0739c70183000048b9167f7ca8bf99f50ba9d1faff1. No bench02 file is modified. `vendor/counts.json` is copied unchanged; its 16 test quotas are extracted at runtime, summing to 2,460. Class order follows the unchanged precedence table.

DATA_PLAN §4.1's strict reading (reference = v_c only, since every W1/W2 source was collected for a §3 target) collapses the ladder to 196k. So the programme §5 line "sized from release v3" governs, and the reference arm is natural frequency over the union.

The E3-frame draw-contract elements stay with the trainer and are not applied in unique-row selection: the parliament 25% draw cap, synthetic 50%, equal optimizer draws, repeats/effective-support disclosure.

Universe: release v3's 168,637 W1/W2 rows plus census_05's 196,234 ADMIT train rows from `collection-v2-train`, keyed by `(parent_id,row_id)`: 364,871 unique rows. The reference permutation sorts these keys then uses Python `random.Random('scale1:reference:20261020').shuffle`. Its 208,000 prefix is strictly nested in its 364,871 prefix, which is the full universe. 420k exceeds supply. The upper point is labelled **"actual maximum; targeted = reference at full universe"**; no separate full-universe targeted file is necessary.

The targeted 208k arm uses original test-quota weights / 2,460. Exact rational water filling saturates classes at their raw supply, redistributes using original quota weights over classes with supply, and repeats. At the final unsaturated step, integer counts use largest remainder, ties in precedence order. This preserves all rows of every short class. If all classes exhaust, append unclassified rows in reference order. It records initial fractional targets, integer allocations, each redistribution step and the unclassified fill count.

Within each class use `Random('scale1:target:20261020:' + class)`. Shuffle sorted sources, then sorted editions for each source, then rows sorted by `(parent_id,row_id)` within each edition, using the same class RNG in sequence. Take one row per source per round; each source rotates editions with a persistent cursor. Exhausted editions leave the queue. Emit class selections in precedence order, then unclassified fill. No subgroup, edition, series, source-frequency or other extra selection filters apply.

Job 1 streams admitted_train twice, retaining compact confidence/key populations in pass one, then writing deterministic gzip (mtime=0, no filename). It calls unchanged bench02 `slim` (including `census05_evidence`) and `tag`. The BENCH02K relative-degraded rule is applied over **all admitted train rows, both parents, per source**: rank available confidence by `(confidence,(parent_id,row_id))`, take first `ceil(.05 * population size)`; missing confidence is never ranked. Null crop_bbox stays absent evidence. No proxy measurements are invented. The receipt reports per-parent/class counts and per-field evidence, census-input, text-facet and tag availability.

Job 2 binds the tags receipt by the coordinator-supplied SHA and hashes the tags file. It hashes every input including large files. W1/W2 labels come from the release; v_c labels come from census final_text with no stripping or Unicode normalization. Crop paths come from census-bound tags, checked against v_c census and release crop hashes. Each subset separately asserts zero SPLIT2 dev/test edition exposure, benchmark keys, benchmark crop-hash matches and original v2 dev/test doc matches for v_c. Every selected crop is physically read and rehashed in every subset. The job fails rather than excluding rows on any audit failure or inconsistent/missing identity. Only a complete run writes a status-ok receipt; an interrupted attempt directory is retained and cannot be reused.

The lead's read-only custody check sampled 2,003 v_c admitted rows (every 98th; 28 sources): 2,003/2,003 crop paths existed and matched crop_sha256. This is supplied evidence; the job still rehashes every selected crop.
