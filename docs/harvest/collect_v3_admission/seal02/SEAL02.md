## Interface to hand to the spell-check lead

Hand over **`seal02/FINAL_LIST.schema.json`**. Its root schema describes each final-list JSONL row; `#/$defs/receipt` describes the companion final-list receipt. The lead can emit these directly from `prod_finalize.py`; do not substitute its current raw-candidate output. No spellcheck files were modified.

```json
{"parent_id":"collect-v3-W1-20261018-0524","row_id":"existing-row-id","split":"test","quota_scope":"test:polytonic","lf1_verdict":"OK","replaces":null,"lf1_receipt_ref":{"verdicts_sha256":"<64 lowercase hex>","line_id":"existing-row-id"},"mock":false}
```

`replaces` is either null or `{"parent_id":"...","row_id":"..."}` for the original in-quota flagged row. `lf1_receipt_ref` resolves the row's `line_id` inside the separately bound merged LF1 `verdicts.jsonl` (the lead's mapper currently calls it `line_verdicts_merged.jsonl`). All candidate IDs must occur once in that ledger, preserving context, verdict, reasons and locations. Reader text is evidence only. A final-list row and its ledger verdict must both be `OK`.

The companion JSON receipt is exactly:

```json
{"status":"FINALIZED","mock":false,"final_list_sha256":"<final-list file sha>","verdicts_sha256":"<LF1 verdicts file sha>","candidates_sha256":"0432c56f75ed1efded00b76e7aeabcc0a2bf9441bfad00e825e4e105006134c2","counts":{"flagged":0,"REPLACED":0,"UNFILLED":0}}
```

Counts apply to originally in-quota rows: flagged = REPLACED + UNFILLED. Supply deficits before LF1 remain distinct in the draw report. Non-OK reserve rows do not count as flagged in-quota slots and cannot be selected. A non-OK in-quota row uses the first still-unused OK reserve within **the same split, primary class, subgroup scope and source**, by recorded rank. If none exists, UNFILLED increases; no padding or cross-source fallback is allowed. Candidate v3's `scope_rank <= quota` implements the coordinator's boundary within split/class[/subgroup]; `rank` retains the class selection order. The adapter validates v3's explicit `in_quota` against that boundary and recomputes the entire expected final set from the ledger. V3 has **2,793 in quota + 548 reserve = 3,341**. In subgroup scopes, `scope_rank` is the recorded subgroup rank; no ordinal is reconstructed from emission order.

The seal rejects any foreign-source promotion or incorrect reserve order.

## Input bindings and image policy

`INPUT_BINDINGS.template.json` binds seven available files: candidates v3, draw plan, counts, readout, tags receipt, live census CURRENT and live generation summary. The first five are exact small input snapshots deployed with the package. The last two are verified at their absolute census paths, with snapshots retained for local tests. Five SHA slots are deliberately null: final list, final receipt, merged verdicts, W1 upload receipt and W2 upload receipt. Production cannot proceed until every slot has an explicit SHA. This template is not a release receipt.

The builder verifies all file bindings, completed census identity, tags-receipt census output digests, full/OK/zero-failure/zero-mismatch CROPS4 receipts, their tranche/heldout flags, output roots and census summary binding. It joins by `(parent_id,row_id)` and rejects duplicate IDs. All present candidate images are rehashed against readout `crop_sha256`; production currently requires all 3,341 candidate images to exist, which is stronger than checking just the selected lines. Selected bytes are copied to `images/<sha256>.png` and rehashed. No recutting, decoding, resampling or normalization occurs. At about 47 MB for all fixture images, copying is inexpensive; actual selected image size is reported by verification, not inferred from that fixture.

Inputs and LF1 evidence are copied into the suite's `evidence/` directory, then rehashed. Per-class and per-subgroup quota/sealed/deficit counts retain each original `counts.json` class report, including its original supply deficits. A successful build writes only one new suite version and its `SEAL_RECEIPT.json`, publishing the fully validated temporary directory by a parent-local atomic rename. An existing output is never overwritten. Failed builds remove their temporary directory and do not publish a suite.
